# 标准链路与审计记录的评估链路

在全链路合规治理的「数据谱系追踪」「全链路追踪」「模型内部审计→训练检查点留痕」选择对象后，点击「保存评估快照」。快照摘要由服务端计算，存入现有 evaluation_workspace_items 表；保存只追加，不提供覆盖或编辑接口，不需要新增数据库表。

保存后可查看逐项核验状态，并点击「使用此快照新建测试任务」。测试评估选择「标准链路与审计记录」也能搜索已保存快照。选定来源后只展示适用于该类来源的指标；执行预检、创建、启动，即可查看逐项明细、证据和导出。

## 固定规则与边界

- 谱系：必须选择数据集/模型的精确版本；冻结当前查询方向和关联子图。按照独立的 data-training-output-v1 三阶段规则检查已登记数据清单、已完成真实训练、模型版本，并检查所选关系的已登记证据。只证明留痕材料存在，不证明训练实际消费了清单、模型质量或标准链路还原正确率；没有独立标准链路时不提供该准确率指标。
- 任务：只接受已完成任务，按 input-time-interface-version-output-v1 检查业务记录中的输入、时间、接口、版本、输出。采用现有任务证据生成规则；字段齐全不等于业务正确。
- 检查点：只接受已完成的真实训练任务。以总轮数的 max(1, epochs // 3) 间隔及最后一轮作为冻结的存档验收规则，不从实际存了几份产物反推要求。只有明确对应轮次（epoch 元数据或最终 last.pt）、且从 8001 下载后字节摘要与登记一致的权重才算已核验。中间轮次没有可对应的产物、服务不可达、无令牌或文件超过 512 MiB 核验限制时保留为无法核验。此规则是本批验收规则，不代表所有训练脚本都承诺每个检查点产生独立权重。

指标均为已核验项/应检查项，默认阈值为 100%，可在指标管理修订。明确缺失的项计入分母；存在无法核验项时结论为「无法判定」，分母为零也不算通过。证据内容完整只表示冻结材料未被篡改，不表示检查项全部通过。

## 权限与留痕

沿用平台登录和只读/操作权限：未登录不可读写，只读账号可查询快照、不能保存。与现有合规模块一致，快照为平台共享记录；创建者 UID 保存于快照中。未实现按部门隔离，不能宣称提供该权限。快照不接收前端上传的分数、状态或证据，服务端按对象查询构建。

快照、冻结输入、逐项结果和导出均采用实际内容 SHA-256。版本不匹配、源快照损坏、冻结输入损坏时拒绝使用；导出前验证证据，下载时再验证文件摘要。业务对象后续修改不会改写已保存或正在评估的材料；重新检查请另存快照。

## 接口

- POST /api/v1/evaluation/audit-snapshots：kind=lineage|task|checkpoints，entity_type=model|dataset|task|training_task，entity_id；谱系还需 version_id 和 direction。
- GET /api/v1/evaluation/audit-snapshots/{id}?version_id={sha256}：读取固定材料。
- GET /api/v1/evaluation/contexts?kind=audit_record：只读查找来源。
- 预检、测试执行、逐项明细、证据、导出复用原测试评估接口。

更新后重启业务后端并刷新前端即可使用，不会自动生成业务快照。真实 8001 服务离线时检查点核验会明确保留缺口。神经元激活、场景覆盖矩阵、复核整改暂不在本批来源中。
