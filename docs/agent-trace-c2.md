# C2 不必要的重复调用

页面、统计和报告统一使用 `app/services/agent_trace_duplicates.py`。
本次只改后端显示与判定逻辑，不修改已保存的原始轨迹或数据库表结构。

## 赛题明确要求

- 判断的是“不必要的重复调用”，参数相同本身不能证明冗余。
- 排除正常轮询、必要复核、状态变化后的重新查询、修复后的重试。
- C2 标记提供本次 `step_id`、前一次 `previous_step_id` 和调用／结果原文证据。
- C5 关联同一标记及证据。没有发现时返回空列表。

## 当前实现如何收集证据

工具名称和规范化参数用于寻找待比较的调用，不直接计数。普通文本保持原值，JSON 键顺序和格式空格不作为差异。
结合保存的助手回复、思考、用户任务和中间操作判断用途；工具返回中的文本不当作调用目的。
原文明确说明冗余时适用于任意工具名称，返回内容完全相等不是所有调用的硬性条件。
另一种可验证情形是：已经取得同一文件的内容，再次读取同一内容，期间没有状态变更或未知作用的操作，
也没有轮询、复核等必要性证据。这是对已知读取动作的实现解释，不是赛题规定的工具白名单。
未知工具行为、单独的重复标签、参数相同、相同报错，均不足以独立认定冗余。

正常轮询、复核、状态更新和修复重试证据优先于冗余推断。失败后的再次尝试不会仅凭相同报错计为重复；
如果原文明确说明未处理失败原因却进行了不必要的重复调用，仍可依据该证据判定。
程序对源日志进行只读分析，不执行任何轨迹命令，不访问命令指向的文件。

移除了旧版页面“三项相同就算重复”的规则，以及赛题仅允许 `read/grep/ls` 等少数工具参与判定的限制。
不再遇到非只读命令就清空历史；已记录的状态变更会阻止不成立的冗余推断，其他读取可继续关联之前的调用。

## 展示与旧数据

同一调用组第一次不计重复，后续每个符合 C2 的调用计一次；每条标记关联实际的前一次调用。
工具页、行为统计、普通报告及赛题报告采用同一判定入口，JSON/ZIP 导出同步更新。
旧快照读取时重新生成 C2 标签和 C5 中对应项，保留原始数据库记录和其他审计结论。
正常重启后端并重新查询即可使用新口径，无需重新上传或执行数据迁移。

这是一套基于可识别原文证据的确定性实现。赛题没有提供完整的自然语言必要性算法，
对无法确认用途或状态的调用保持保守，不承诺识别所有表达方式；不能将未标记解释为已证明必要。
