一agent介绍：agent能根据LLM的思考，从而调用工具，使用react的工作范式即思考行动观察。自主性：可以通过自己思考，从而规划出任务分为哪几步，通过调用工具，访问记忆，感知环境来一步步执行。
普通大模型的局限性：知识过期，不能行动，私有领域知识缺失
agent特别在：1.agent能过通过mcp协议调用工具（能动），2.记忆机制：长期记忆，短期记忆，长期通过向量库/数据库存储（如私有知识库，用户的喜好，历史操作记录），短期记忆：context window复杂任务分步之后，当前处于哪个阶段，前面做了哪些事情。LLM通过决策输出要调用工具的JSON字符串，代码也就是agent解析json调用外部的服务，3.多步推理以及自我纠错：这是区别于自动化脚本的关键。
二agent的基本架构有LLM,工具（模型本身不执行只决策，也就是决策和执行分离），推理模块，记忆系统
workflow是指将agent,tool,llm组合在一起，并通过代码规定工作流程。 workflow编排模式  prompt chain(提示链) ：把大任务拆分成多个小步骤，前一步的暑促作为后一步骤的输入，root（路由）：先用一个LLM做分类判断，然后根据分类结果把请求分发到不同的处理分支， parallelizaton（并行） 同时从多个 数据源检索信息。Orchestrator-Workers(编排者-工人)一个中英编排者负责分配任务，多个worker各自完成子任务。Evaluator-Optimizer(评估者-优化者)：一个模型输出，另一个模型负责评估这个输出，不合格重新生成
四agent的范式有 ReAct,Plan and Execute ,reflection  ReAct是思考 行动 观察 也就是做一个看一步 思考这一步可以避免agent想到某一个工具就去调用，这种工作范式会使得在进行复杂性工作的时候，会忘记最初的目标是什么，比如被搜索结果吸引还有就是错误传播 某一部出错后面都出错。改进 Plan-and-Execute  先提前做一个规划，然后再去执行每一步，但执行完每一步会进行反馈，看一看需不需要调整  还可以进行解耦  将推理（推理模型 强 贵）与执行分（执行模型 弱 便5B9C）为两个模型    reflection 会在执行完某一步执行进行反思  reflexion会在执行完某一步之后进行反思，将反思作为额外的上下文传给下一次尝试。
五推理模式有  Chain of Thought（CoT） React   Tree of Thought(ToT)  Self-Reflection  Graph of Thought(GoT)
六 三种范式  React 灵活度高 但容易跑偏和错误传播，Plan-and-Execute 用于长流程复杂任务，不容易跑错，Reflection是在前面两个范式中加入一个检查的buff 设计范式指的是你的agent的顶层做事流程框架  推理模式是你agent在每一步干活是的脑子具体是怎么想的。
七 复杂任务怎么划分 为什么划分 是因为上下文（context window）有限  任务复杂容易导致中间状态过多，模型很难追踪到子目标，容易造成桌面太乱出错 让一个人同时记住十件事并做对以及记住一件事情并做对   并且每个步骤都是独立输出的 如果某一个步骤出错 检查这个步骤就行 拆分完还有一个好处 就是可以判断哪些步骤可以并行 端到端的延迟降低很多 划分方法  静态划分 提前把步骤写死   动态划分  通过 让LLM通过自己的规划划分步骤   
RAG的检索策略构建导图
1什么是agent  agent是能独立自主完成任务的ai系统，它与大模型最大的区别在于自主性能能动性，LLM是简单的一问一答，而agent可以给它一个复杂的任务，让他自主的去规划步骤，调用工具。
2.agent的组件 有LLM， 规划模块，记忆模块，工具系统。 LLM是大脑，推理模块是将复杂任务分解成一个个步骤，分步执行。
3，workflow是已经固定了的工作流程，而agent的是workflow的组成部分，workflow是将所有的决策都写好了，workflow可以由agent  tool LLM构成，可以在需要灵活的地方增加一个agent
4.agent 的设计范式  React  Plan-execute  React是思考 执行观察  Plan-execute是先将一个复杂的任务进行规划，划分成一个小小的任务，将任务规划与任务执行进行解耦这样的好处是可以将并行执行的子任务并行执行，缩短复杂任务的处理时间，而context window是有限的，还可以防止由于中间状态过多，大模型忘记本来的任务目标，导致跑偏
5.SSE技术客户端通过http请求与服务端进行连接，保持连接，除了最初建立连接的请求外，不能像服务端进行通信，服务端持续的像客户端发送内容。
6，熔断机制，增强系统的健壮性，当系统的出错时，进行统计，统计次数过多的时候，打开熔断，走降级方案，并记录一个时间，当时间超过设定的时间的时候，打开半开模式，试探性的不走降级方案，存储失败次数，如果失败次数过多则再次打开熔断器，放在工具执行后。
7.回溯：工具回溯：工具不好用，计划回溯：计划规划的好不好，状态回溯，一般来说先回溯，达到阈值，再熔断
8.上下文存会话记忆，当前的任务，执行结果，使用的工具，任务的进度，结束会话后从上下文中结构化一些用户画像（偏爱什么语言，最近在做什么，- 实体关系（用户提到的人、项目、工具之间的关系），用户的身份：老师，学生，从业人员，还是爱好者）保存到数据库当中，讨论过的方案、最终选择、选择原因，这类情节记忆放入到向量数据库中。
9.记忆压缩的方法：截断，摘要，重要性过滤，结构化信息。混合（k轮保留，k-2k轮摘要	2k-> 重要性过滤，结构化提取）
10.记忆更新是能否精准替换：可以 1.基于id2.基于语义相似性
11存储前后不一样：时间戳优先策略，置信度打分：每条记忆附带置信度分数，多次提及置信度上升，出现矛盾降低旧记忆的置信度。
12.意图识别的方式大模型进行识别：1.为每个agent进行详细的描述通过提示词，通过提示词进行区分，2.语义相似度：将描述嵌入向量
13.怎么提高意图识别的准确性：1.为每个agent编写清晰的能力描述，2.上下文增强：不只看当前消息，看当前的的上下文3.多级路由：第一级粗分，第二级细分
14.为什么选择sse不选择worksocket，see是跑在http上面的，可以直接复用现有的http生态，sse比worksocket更轻量，且sse内建自动重连机制，sse的客户端向服务端发送http请求，服务端保持连接，且持续不断的向服务端发送消息，用户看着回复很像打字。
